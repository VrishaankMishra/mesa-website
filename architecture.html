MeSA 2.0 · architecture and stack

How it's built.

One Python process on a Raspberry Pi 5. Two worker threads watch the camera and the microphone and publish events onto one queue. A decision engine reads the queue and decides what to log, say, or send. Nothing leaves the house.

The shape of it

One process, one queue.

There is no message broker, no network between parts, no cloud. The vision thread and the audio thread put typed events on a queue; the engine takes them off in order and advances its state machines using each event's own clock, which is also what makes the timers testable with simulated time instead of sleeps.

Every threshold lives in one config.yaml: frame rates, confidence cut-offs, debounce times, escalation waits, the alert topic. Changing behaviour means editing one file, not code.

Subsystems

What each part does, and what it's built on.

Seeing bottles

OpenCV grabs 640×480 frames. Every third frame goes to a YOLOv8n detector fine-tuned on the eight medications in this house plus a "tray" class. A box under 0.45 confidence is relabelled unknown, which is the wrong-medication path. The camera's exposure, white balance and focus can be locked at a station, or left on auto.

  • opencv-python 4.10
  • ultralytics 8.2
  • numpy 1.26

mesa/vision/detector.py · camera.py · worker.py

Standing, sitting, lying

MediaPipe Pose runs on every frame. The posture label is smoothed with a 15-frame majority vote, leg landmarks below 0.5 visibility are ignored, and a torso the model cannot see is refused rather than guessed. A body that reads as lying for 30 seconds raises possible_fall; a dropout under 5 seconds does not cancel the spell. Measured at 20.7 frames per second on the Pi.

  • mediapipe 0.10

mesa/vision/pose_estimator.py · posture.py

Was it taken?

Each bottle has its own two-state machine. A reading has to disagree for 3 seconds before the state flips, so a hand passing over a bottle changes nothing. Absent for at least 10 seconds and then back on the table is a taken event, timestamped and written to the database.

  • Python stdlib

mesa/engine/presence.py · compliance.py

Talking to it

Push-to-talk instead of a wake word: a key or a GPIO button opens a 6-second window. Vosk decodes offline against a grammar of about 60 phrases, so a noisy room cannot produce words that were never said; names the small lexicon lacks get spoken aliases. Intents cover the next dose, did-I-take, call for help, the time and date, and "I am okay". Replies are spoken by pyttsx3. An open-vocabulary faster-whisper engine sits behind the same interface.

  • vosk 0.3.44
  • faster-whisper 1.2
  • pyttsx3 2.90
  • sounddevice 0.4

Deciding and escalating

The engine consumes events and drives three state machines: compliance, fall, inactivity. A possible fall opens a spoken check-in and a 30-second listening window that needs no button press. No answer in 60 seconds sends a push to the caregiver's phone (L2); another 60 seconds raises the caregiver alert (L3). "I am okay" clears it at any level. An hour with nobody seen starts the same chain.

  • Python stdlib
  • requests 2.32

Remembering and showing

SQLite through the standard library, three tables: events, medications, schedule. A Streamlit page on the home network shows today's doses as taken or due and the last fifty events. A phone on the same Wi-Fi can open it.

  • sqlite3 (stdlib)
  • streamlit 1.38

mesa/data/database.py · mesa/dashboard/app.py

A face and a head

A pan/tilt servo head that keeps the person centred and a small OLED face that shows the robot's state sit behind plug modules. When the libraries or the I²C bus are absent, the same code runs against null drivers, so a laptop with no hardware runs the whole system and its tests.

  • gpiozero 2.0
  • adafruit-circuitpython-pca9685 3.4
  • adafruit-circuitpython-ssd1306 2.12

mesa/hardware/servos.py · tracking.py · oled.py · emotions.py

Measuring itself

A rolling buffer keeps the last seconds of per-frame features, and every real taken event labels the window before it as a clip. The evaluation scripts turn a voice-guided placement protocol into ground truth for free: that is how the lighting study was collected without hand-labelling a frame.

  • Python stdlib

How it's developed

Laptop first, then the Pi.

Everything is written and tested on a laptop with no hardware attached, then deployed to the Pi. Hardware libraries are imported in isolation so the tests never need them. Dependencies are pinned to exact versions in two requirement files, one for the laptop and one for the Pi. Python 3.11 on both.

The test suite runs the engine against synthetic events with simulated clocks, so an escalation that takes two real minutes is tested in milliseconds. main.py --demo plays a scripted sequence end to end without a camera; main.py --live starts the workers for real. A systemd unit starts it on boot.

Left out on purpose

What isn't in it.

No always-on wake word: the first demo in a loud room showed it was the weakest link, so a button replaced it. No video recording: frames are processed and dropped, and the research clips keep numbers, not pictures. No cloud and no account: the alert is a plain HTTPS post to a topic the caregiver subscribes to, and that is the only packet that leaves the house.
